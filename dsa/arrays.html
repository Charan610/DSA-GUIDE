Arrays & Dynamic Arrays

An array is a contiguous block of memory storing elements of the same type under sequential numeric indices. Because memory locations are adjacent, any element can be retrieved instantly in O(1) time using base address mathematical calculation.

Random Access O(1)
Insert / Delete O(n)
Search (Unsorted) O(n)
Space Complexity O(n)

📄 Standard Array Operations Pseudocode
▼ 
// Access element by index
function getElement(arr, index):
    if index < 0 or index >= arr.length:
        throw IndexOutOfBoundsException
    return arr[index] // O(1) time calculation: base_addr + (index * element_size)

// Insert element at specific index
function insertAtIndex(arr, index, element):
    for i from arr.length - 1 down to index:
        arr[i + 1] = arr[i] // Shift elements to the right
    arr[index] = element

Common Mistakes & Gotchas

  • Off-by-one errors: Attempting to access arr[arr.length] instead of arr[arr.length - 1] causes out-of-bounds exceptions.
  • Assuming O(1) insertions: Inserting at the beginning or middle of an array requires shifting trailing elements right, making it an O(n) operation.
  • Ignoring dynamic resizing overhead: When dynamic arrays reach capacity, reallocation creates a new array of double size and copies elements over, yielding O(n) worst-case resize time (amortized O(1)).

Practice Challenge

Q: Given an array [10, 20, 30, 40], what is the exact time complexity of deleting the element at index 0 versus index 3, and why?

Answer:

Deleting index 0 takes O(n) time because all remaining n-1 elements must be shifted one position left to keep memory contiguous.

Deleting index 3 (the last element) takes O(1) time because no remaining elements need shifting.
