Stacks & Queues

Stacks and Queues are fundamental linear data structures with constrained insertion and deletion rules. A Stack operates on a Last-In, First-Out (LIFO) protocol (like a stack of plates), whereas a Queue operates on a First-In, First-Out (FIFO) protocol (like a line of people waiting).

Stack Push / Pop O(1)
Queue Enq / Deq O(1)
Search O(n)
Space Complexity O(n)

// Stack (LIFO) Push & Pop
class Stack:
    function push(item):
        arr.append(item) // O(1)

    function pop():
        if isEmpty(): throw UnderflowError
        return arr.pop() // O(1) removes top element

// Queue (FIFO) Enqueue & Dequeue
class Queue:
    function enqueue(item):
        tail.next = new Node(item) // O(1)
        tail = tail.next

    function dequeue():
        if isEmpty(): throw UnderflowError
        val = head.data
        head = head.next // O(1) removes front element
        return val

Common Mistakes & Gotchas

  • Using array shift() for queues in JS/Python: Removing from index 0 of a standard array forces an O(n) shift of all remaining elements. Use a linked list or circular buffer for true O(1) queue dequeues.
  • Stack Underflow: Popping or peeking from an empty stack without an isEmpty() check causes null/undefined access exceptions.
  • Unbounded recursion: Recursive call stacks consume function frame memory. Deep recursion without base cases triggers a Maximum Call Stack Size Exceeded error (Stack Overflow).

Practice Challenge

Q: How can you implement a Queue using two Stacks (In-Stack and Out-Stack), and what is the amortized time complexity of the enqueue and dequeue operations?

Answer:

Enqueue: Push element onto In-Stack in O(1) time.

Dequeue: If Out-Stack is empty, pop all elements from In-Stack and push them into Out-Stack (reversing their order to FIFO). Then pop from Out-Stack. Each element is moved at most twice, yielding an amortized O(1) time complexity for dequeue.
