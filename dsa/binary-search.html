Binary Search

Binary Search is an efficient divide-and-conquer algorithm for finding an item in a sorted array. By repeatedly halving the search window based on comparing the middle element with the target, it reduces search space exponentially, finding any element among 1,000,000 items in 20 steps or fewer.

Best Time O(1)
Average / Worst O(log n)
Prerequisite Sorted Array
Space Complexity O(1) Iterative

📄 Iterative Binary Search Pseudocode
▼ 
function binarySearch(arr, target):
    low = 0
    high = arr.length - 1

    while low <= high:
        // Avoid integer overflow in languages with bounded 32-bit ints:
        mid = low + Math.floor((high - low) / 2)

        if arr[mid] == target:
            return mid // Target found!
        else if arr[mid] < target:
            low = mid + 1 // Target is in right half
        else:
            high = mid - 1 // Target is in left half

    return -1 // Target not found

Common Mistakes & Gotchas

  • Using Binary Search on unsorted input: Binary Search assumes monotonic order. If the input array is unsorted, the decision to discard half the array is invalid and returns incorrect results.
  • Integer overflow in mid calculation: Writing mid = (low + high) / 2 can overflow maximum integer limits for huge arrays in languages like C++/Java. Use low + (high - low) / 2 instead.
  • Infinite loops with boundary updates: Setting low = mid or high = mid instead of mid + 1 / mid - 1 leads to infinite loops when low and high neighbor each other.

Practice Challenge

Q: Given a sorted array of 1,024 elements, what is the maximum number of comparisons Binary Search will make in the worst-case scenario?

Answer:

11 comparisons maximum (since \( \lceil \log_2(1024) \rceil = 10 \), plus 1 final check for 1-element remaining). Halving 1024 takes: 1024 ➔ 512 ➔ 256 ➔ 128 ➔ 64 ➔ 32 ➔ 16 ➔ 8 ➔ 4 ➔ 2 ➔ 1.
